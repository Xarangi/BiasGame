BiasGame: implementation plan

Evidence that the experiments will land, then the build: code structure on SiliSocs, engineering contracts, study execution, budgets, and timeline.

Prepared August 8, 2026 · Companion to the Experimental Design Proposal and Literature Review

1Will these experiments produce actionable results?

Assessment

Yes, with high confidence — every measurement channel in the design has a nonzero-effect precedent in an adjacent (weaker) paradigm, and our paired counterfactual design is strictly more sensitive than the designs that already found effects. The main scientific risk is not a null result; it is that effects are so pervasive that the contribution must come from the structure of the findings (process vs. outcome, horizon curves, mechanism tests) — which is exactly what the design measures.

Actionable for whom: (a) model developers — process-level bias diagnostics are trainable targets and system-card material (Anthropic already ships DiscrimEval numbers; this is its agentic successor); (b) deployers — per-setting risk profiles ("this model is clean in triage but biased in delegation") map to real procurement decisions; (c) mitigation research — H10's context surgery, if positive, hands the field a mechanism-backed mitigation (context hygiene) rather than another prompt patch; (d) audit/policy — the four-fifths-rule analysis on agentic queues speaks the language NYC Local Law 144-style audits already use.

2System architecture and repo layout

Engineering contracts (the four invariants everything else leans on)

  1. Slot-token discipline. World content refers to people only as ⟦P1⟧…⟦P5⟧. The linter enforces it at compile time; the firewall is the only code that resolves tokens. Any component wanting person-text goes through firewall.render() — no exceptions, including probes and intervention text.
  2. The leak test is a CI gate, not a test. For every world template and backend: run two permutations with the identity layer stubbed to neutral tokens; transcripts must be byte-identical. A red leak test blocks merge. This single check converts the counterfactual claim from "we were careful" to "it cannot leak."
  3. Determinism budget. T1 personas and rule-based GMs are exactly deterministic (replay test). T2 personas are temp-0 + cached. The subject model is the only irreducible stochasticity — handled by seeds × repeats in the study matrix, never by averaging away within a run.
  4. Judge hygiene. All LLM-judge scoring (tone, hostility, hedging) runs on re-anonymized transcripts (identities mapped back to neutral tokens), so judge bias cannot correlate with condition. Every judge measure ships with a human-validation κ on a ≥300-item split.

3Build order

Phase 0Spineweeks 1–3

Fork + pin SiliSocs; schema.py, firewall.py, permutations.py; interview.py + queue_desk.py MVP (5 tickets, no tools); T1 personas; probe configs; JSONL → tidy-df loader.

Exit: one hand-written Service Desk world runs end-to-end under 2 permutations with a scripted subject; leak test and replay test green in CI.

Phase 1Compiler + pilotweeks 3–6

World compiler from BBQ seeds (race/ethnicity + gender first) with linter; identity packages incl. dialect transforms; bayes.py + CFR/ABS/SCR/EDG scorers; judge harness. Pilot: Worlds 1+4, 10 skeletons × 4 permutations × 2 seeds × 3 models (one ~8B open, one ~70B open, one frontier API).

Exit: pilot effect sizes + variance components → power analysis fixes the Phase 3 matrix; go/no-go on CPB (the novelty bet) with 10 archive worlds.

Phase 2Validation (Study 1) + pre-registrationweeks 6–10

Reliability (regeneration, paraphrase, split-half); generator swap (compiler on two unrelated model families — firewall predicts measure agreement; this is P2's falsifiable check); manipulation checks; human scenario audit (realism + leakage, ~300 items, 3 raters); convergent validity runs (BBQ, DiscrimEval, LLM-IAT on the same models). OSF pre-registration of Study 2/4 endpoints (primary: CFR, ABS, EDG; the rest exploratory).

Exit: pre-registration frozen; instrument paper–grade validation table complete.

Phase 3Main sweep (Studies 2 + 4)weeks 10–14

Study 2: Worlds 1+4 (2 if budget), 4 BBQ categories × 20 skeletons × 5 permutations × 2 seeds × 12 models ≈ 19.2K episodes/world. Short-episode configuration (~15–25 subject calls each) keeps this ≈ 300–500M subject-side tokens/world — roughly $1.5–4K at open-weight serving prices plus $2–5K frontier API, well inside a lab budget; Slurm via SiliSocs' Submitit path, resumable checkpoints throughout. Study 4: 4 models × 3 horizon arms (10/40/120 steps) × 12 worlds × 5 permutations on World 1 — the 120-step arm dominates cost, budget ≈ equal to Study 2.

Exit: pre-registered endpoints analyzed; bias-profile cards + bias–horizon curves rendered from reports.py.

Phase 4Mechanisms (Study 3) + releaseweeks 14–18

Moderators on the 4 most informative models: marking modality (explicit/name/dialect), pressure, eval-salience (with awareness probes), mitigation prompts. H10 context surgery: checkpoint at step k, sanitize the subject's own skewed turns from history, resume, compare. Release: frozen world library v1.0 + compiler + harness + study YAMLs; upstream PR to SiliSocs (firewall component + backends); paper.

Exit: arXiv preprint; reproduction runs from a clean clone with one run_study command.

4How experiments actually run

The entire matrix is SiliSocs study configs — no bespoke orchestration. Sketch:

# studies/study2_main.yaml
hypotheses:
  h1_divergence:
    conditions:
      # one condition per (world_template, category, permutation)
      svc_race_pi0: { overrides: { world: service_desk, category: Race_ethnicity,
                                   permutation: latin_row_0 } }
      svc_race_pi1: { overrides: { permutation: latin_row_1 } }
      # ... generated programmatically by studies/gen_matrix.py
    execution: { mode: run, seeds: [11, 17] }
evaluators: [cfr, abs, edg, scr, judge_tone]
  • Provenance: every episode logs (world hash, π, seed, model, silisocs tag, biasgame git SHA) into the run manifest; measures are recomputable from committed JSONL alone.
  • Cost control: T1 personas are free; the subject is the only per-token cost in Studies 1–2. A cost ledger per model per study lives in experiments/, updated by the runner.
  • Failure handling: episodes are checkpoint-resumable; a failed model/provider marks conditions reuse_existing on rerun so completed permutation partners are never re-bought.
  • Analysis: analysis/models.py fits mixed-effects models (crossed world × model REs), exact permutation tests within matched sets, BH correction across categories; notebooks consume tidy dataframes only.
